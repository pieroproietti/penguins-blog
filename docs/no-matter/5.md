# Capitolo 5: Il ciclo vitale (Guide pratiche e flussi di lavoro)

La teoria e l'architettura si misurano sui comandi e sui clic reali. A seconda di dove ci si trova — se immersi in un ambiente desktop o confinati nel silenzio di una riga di comando — il flusso operativo si divide in due percorsi distinti.

## Percorso A: La via visiva (tramite [`penguins-gui`](../gui/index.md))

Se ci si trova già all'interno di un sistema desktop funzionante, la strada più rapida ed ergonomica passa attraverso l'interfaccia grafica.

1. **Scaricare e avviare la GUI:** 
   Basta prelevare l'AppImage di `penguins-gui` direttamente dai canali ufficiali e renderla eseguibile:
   ```bash
   chmod +x penguins-gui-*.AppImage
   ./penguins-gui-*.AppImage
   ```
2. **Configurazione e repository:** 
   Dal menu `Edit → Install penguins-egg CLI`, la GUI stessa guiderà l'utente nelle operazioni preliminari, compresa l'aggiunta automatica del repository nativo di `eggs` e l'installazione del motore.
3. **La cucina e la produzione:** 
   Attraverso il cruscotto grafico si possono richiamare le ricette di `penguins-chef` (pulsante **Cook**), ripulire il sistema (**Clean**) e lanciare la produzione dell'immagine ISO (**Create ISO**) con un semplice clic.

## Percorso B: La via del terminale (tramite CLI)

Se operiamo su un server headless, su un sistema minimale (`naked`) o semplicemente preferiamo il controllo diretto della shell, il percorso passa per l'installazione nativa e la CLI.

1. **Scaricamento e installazione:**
   Si scarica il pacchetto nativo per la propria distribuzione direttamente da [GitHub Releases](https://github.com/pieroproietti/penguins-eggs/releases/latest) o dal [basket di penguins-eggs.net](https://penguins-eggs.net/basket/), installandolo con il gestore pacchetti della propria distro (`apt`, `pacman`, `dnf`, `zypper` o `apk`).
   
2. **Aggiunta del repository nativo:**
   Una volta che `eggs` è installato sul sistema, non servono script complessi o comandi manuali di configurazione dei listati: basta un comando nativo dell'utility per configurare i repository ufficiali e le chiavi GPG della propria distribuzione:
   ```bash
   sudo eggs tools repo add
   ```
   *(Da questo momento è possibile installare e aggiornare anche [`penguins-chef`](../chef/3-quickstart-e-cli.md) per cucinare ricette e costumi YAML).*

## La produzione della ISO (`eggs remaster`)

Indipendentemente dal percorso scelto (GUI o CLI), una volta che il sistema è pulito (`sudo eggs tools clean`) e configurato, si procede alla creazione dell'immagine:

* **Produzione standard (sistema generalizzato per nuovi utenti):**
  ```bash
  sudo eggs remaster
  ```
* **Clonazione esatta dell'habitat (preserva utenti e `/home`):**
  ```bash
  sudo eggs remaster --clone
  ```
* **Produzione con cifratura LUKS2 (famiglia Debian):**
  ```bash
  sudo eggs remaster --crypted
  ```

## Test e installazione (tramite Krill o Calamares)

Ottenuta la ISO in `/home/eggs`, l'immagine può essere avviata direttamente da disco tramite GRUB (`eggs tools grub40`) oppure scritta su chiavetta USB:

```bash
sudo dd if=/home/eggs/nome-immagine.iso of=/dev/sdX bs=4M status=progress && sync
```

Avviato il computer di destinazione con la live, la scelta dell'installer dipende dalle preferenze di chi gestisce la macchina:

* **La via testuale con `krill`:**
  Richiamando l'installer TUI direttamente da terminale:
  ```bash
  sudo eggs sysinstall krill
  ```
  `krill` guiderà l'amministratore nella gestione avanzata delle partizioni, dei mount point personalizzati (inclusa la preservazione di `/home` esistenti) e della [coesistenza multi-boot (`eggs coexist`)](../eggs/coexist.md).

* **La via grafica con Calamares:**
  Se durante la preparazione del sistema si è scelto di integrare Calamares (ad esempio da `penguins-gui` andando su `Edit → Install calamares`), l'installer grafico verrà configurato in modo completamente automatico all'interno della ISO. Al boot della live basterà avviare Calamares dal desktop (oppure digitare `sudo eggs sysinstall calamares`) per procedere all'installazione con un'interfaccia visiva familiare e guidata.

In entrambi i casi, al termine del processo il guscio si schiuderà, restituendo al riavvio lo stesso identico habitat di partenza.
