# Capitolo 5: Il ciclo vitale (Guide pratiche e flussi di lavoro)

La teoria e l'architettura si misurano sui comandi e sui clic reali. A seconda di dove ci si trova — se immersi in un ambiente desktop o confinati nel silenzio di una riga di comando — il flusso operativo si divide in due percorsi distinti.

## Percorso A: La via visiva (tramite penguins-gui)

Se ci si trova già all'interno di un sistema desktop funzionante, la strada più rapida ed ergonomica passa attraverso l'interfaccia grafica.

1. **Scaricare e avviare la GUI:** 
   Basta prelevare l'AppImage di `penguins-gui` direttamente dai canali ufficiali e renderla eseguibile:
   ```bash
   chmod +x penguins-gui*.AppImage
   ./penguins-gui*.AppImage
   ```
2. **Configurazione e repository:** 
   La GUI stessa guiderà l'utente nelle operazioni preliminari, compresa l'aggiunta automatica del repository nativo di `eggs` necessario per la gestione dei pacchetti e degli aggiornamenti.
3. **La cucina e la produzione:** 
   Attraverso il cruscotto grafico si possono richiamare le ricette di `penguins-chef`, ripulire il sistema e lanciare la produzione dell'immagine ISO con un semplice clic.

## Percorso B: La via del terminale (tramite CLI)

Se operiamo su un server headless, su un sistema minimale o semplicemente preferiamo il controllo diretto della shell, il percorso passa per l'installazione nativa e la CLI.

1. **Scaricamento e installazione:**
   Si scarica il pacchetto per la propria distribuzione direttamente da [penguins-eggs.net](https://penguins-eggs.net) o da SourceForge, installandolo con il gestore pacchetti della propria distro (ad esempio con `apt`, `pacman`, `dnf` o `zypper`).
   
2. **Aggiunta del repository nativo:**
   Una volta che `eggs` è installato sul sistema, non servono script complessi o comandi manuali di configurazione dei listati: basta un comando nativo dell'utility per configurare i repository ufficiali della propria distribuzione:
   ```bash
   sudo eggs tool repo add
   ```

## La produzione della ISO (`eggs produce`)

Indipendentemente dal percorso scelto (GUI o CLI), una volta che il sistema è pulito e configurato, si procede alla creazione dell'immagine:

* **Produzione standard:**
  ```bash
  sudo eggs produce
  ```
* **Clonazione esatta dell'habitat:**
  ```bash
  sudo eggs produce --clone
  ```
* **Produzione con cifratura LUKS:**
  ```bash
  sudo eggs produce --luks
  ```

## Test e installazione con `krill`

Ottenuta la ISO in `/home/eggs`, l'immagine può essere scritta su chiavetta USB:

```bash
sudo dd if=path/to/eggs-image.iso of=/dev/sdX bs=4M status=progress && sync
```

Avviato il computer di destinazione, per installare la live sul ferro vivo si richiama l'installer testuale:

```bash
sudo krill
```

`krill` guiderà l'amministratore nella gestione delle partizioni, dei mount point e della coesistenza multi-boot, completando il ciclo e restituendo al riavvio lo stesso identico habitat di partenza.

## Test e installazione (tramite Krill o Calamares)

Ottenuta la ISO in `/home/eggs`, l'immagine può essere scritta su chiavetta USB:

```bash
sudo dd if=path/to/eggs-image.iso of=/dev/sdX bs=4M status=progress && sync
```

Avviato il computer di destinazione con la live, la scelta dell'installer dipende dalle preferenze di chi gestisce la macchina:

* **La via testuale con `krill`:**
  Richiamando l'installer TUI direttamente da terminale:
  ```bash
  sudo krill
  ```
  `krill` guiderà l'amministratore nella gestione avanzata delle partizioni, dei mount point personalizzati e della coesistenza multi-boot.

* **La via grafica con Calamares:**
  Se durante la preparazione del sistema tramite **`penguins-gui`** si è scelto di integrarlo (andando su `Edit` -> `Installa Calamares`), l'installer grafico verrà configurato in modo completamente automatico all'interno della ISO. Al boot della live basterà avviare Calamares per procedere all'installazione con un'interfaccia visiva familiare e guidata.

In entrambi i casi, al termine del processo il guscio si schiuderà, restituendo al riavvio lo stesso identico habitat di partenza.
